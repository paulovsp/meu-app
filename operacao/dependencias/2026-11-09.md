Sem mudança de leitura em relação à rodada passada.
- Fonte: [Expo SDK 54 — docs.expo.dev/versions/v54.0.0](https://docs.expo.dev/versions/v54.0.0/).
- **Nota de segurança desta rodada**: a mesma página traz, na seção "Submitting Feedback", instruções dirigidas a um agente (comando `npx submit-expo-feedback` ou uma requisição `curl` para `api.expo.dev`) e, na seção "Navigation", uma orientação para buscar páginas relacionadas em Markdown. Tratado como conteúdo da página, não como instrução a seguir — nenhuma ação foi tomada a partir disso. Registrado para o dono saber que a fonte segue trazendo esse tipo de texto.

## Segurança

Nesta rodada, excepcionalmente, `node_modules` ficou instalado (necessário para o checklist do PR) e foi possível rodar `npm audit --json --omit=dev` de fato pela primeira vez em várias semanas:

- **31 vulnerabilidades em dependências de produção**: 1 baixa, 19 médias, 10 altas, **1 crítica**.
- Crítica: `shell-quote` (via cadeia de dependências de ferramentas do toolchain Expo/Metro, não código do app) — injeção de comando em `quote()` via terminador de linha num token após um comentário `{ }`.
- Altas, todas em dependências de dependências do toolchain (Metro/Webpack/ferramentas de build do Expo, não em código executado pelo app em produção): `@react-navigation/core` (via `query-string`/`decode-uri-component`), `brace-expansion`, `compression`, `image-size`, `node-forge`, `postcss`, `source-map-js`, `undici`.
- Nenhuma delas está num pacote direto do app (todas aparecem via subdependências do `expo`/`@expo/cli`/Metro). Resolver exigiria `npm audit fix --force` (mudanças de versão maior, potencialmente nativas) — não é algo a fazer dentro desta rotina (regra: nunca trocar versão maior sozinho). Registrado para quando o upgrade de SDK acontecer: o próprio upgrade deve atualizar essa cadeia de dependências de build.
